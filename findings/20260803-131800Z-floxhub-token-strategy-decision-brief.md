## Unknowns / assumptions not yet verified

1. **`--token-file` + machine token interchangeability (issue #16's flagged unverified assumption) — still unverified.** Public docs describe `--token-file` in user-token terms only. Confirming this requires either an actual machine token (which requires contacting Flox and likely a paid org) or a direct answer from Flox support/docs not surfaced by this research pass.
2. **Whether machine-token provisioning is included in the $20/seat Team tier or requires Enterprise/custom pricing.** The organizations doc says to "contact the Flox team to request a client ID and secret" — this reads as a manual/gated process regardless of tier, not a self-service flow, so real cost may not be simply "$20 × seats."
2b. **Whether a machine token can be issued at Reader scope specifically**, vs. Reader being a role assigned to *user* members and the machine token instead inheriting some other/broader scope by default. Docs describe Reader as an org RBAC role and machine tokens as authenticating "as the organization itself" — it's not stated whether machine tokens can be minted per-role or only as one fixed org-level scope.
3. **Cachix paid-tier dollar pricing** is not published; Starter/Standard/Pro storage tiers (50/250/1500 GiB) are gated behind a sales contact, so no real cost comparison against Flox Team's published $20/seat is possible without reaching out.
4. **Self-hosted substituter cost/effort** is a rough estimate only (S3 + `nix-serve`/similar + signing-key rotation) — no concrete pricing was pulled since it depends entirely on infra choices not yet made.
5. **Drop-in-swap confirmation for Option B** (re-running Stage 6 with a machine token instead of a personal one) has not been attempted — flagged in the original prompt as something that needs an actual token to verify, which this desk-research pass explicitly could not do (out of scope: no signups, no org creation, no money spent).

## Recommendation (not a decision)

Given that:
- Option A is free, fully proven today, and requires zero new work to keep using — issue #16 §9 already defaults to it for exactly this reason.
- Option B's core selling point (narrower blast radius via Reader-scoped machine tokens) is real and documented, but its mechanics with `--token-file` remain unconfirmed, and its actual provisioning path is gated behind contacting Flox's team rather than a clean self-serve flow at a known price — so the "cost" line item is fuzzier than the $20/seat headline suggests.
- The Cachix/self-hosted fallback is a materially different, lower-polish path (no `flox auth`/`pkg-path` UX) that only becomes relevant if Teams pricing is confirmed to be a blocker — which it hasn't been, since Option B's actual price for machine-token access specifically hasn't been pinned down.

**My read**: staying on Option A for the Phase D MVP (as §9 already defaults to) is the lower-risk path short-term, since it's proven and free. Moving to Option B would need one concrete unblocking step first — actually contacting Flox (or finding someone who already has a Team/org account) to mint a real machine token and confirm the `--token-file` swap works — before it can be treated as a validated alternative rather than a plan that reads well on paper.

That said — **this is Elvis's call; the above is what it takes to make it quickly.** If the personal-account exposure of Option A is judged unacceptable regardless of cost/effort (e.g. for gtm-sdk CI specifically, not just this sandbox), that argument overrides the "free and proven" case for Option A on its own.
